# M4 – Besucher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Gäste reisen nach „Festival starten“ mit dem Auto über eine feste Zufahrtsstraße und das Wegenetz an, bauen ihr Zelt auf einer vom Spieler aufgezogenen Zeltfläche auf, laufen über Wegweiser-Karten zu Bier, Essen, Klo, Bühne und Merch, zeigen Denkblasen und reisen nach drei Festivaltagen (oder früher, wenn sie sehr unzufrieden sind) wieder ab.

**Architecture:** Alles Spielgeschehen liegt in Phaser-freien Modulen. Das `Grid` bekommt zwei neue Ebenen (Zeltfläche, „belegt durch Zelt/Auto“). `RoadNetwork` berechnet, welche Wege an der Straße hängen; darauf bauen Lieferregel, Zeltflächen-Anschluss und Auto-Routen auf. Eine `Festival`-Klasse besitzt Uhr, Zufall, Angebote (Wegweiser-Karten und Schlangen), Autos, Zelte und Gäste und rechnet in festen Zeitschritten (Ticks). `WorldScene` zeichnet Straße, Zeltflächen und alle Figuren über eine `VisitorView`; `UIScene` zeigt Uhr, Start-Knopf, Gesamtanzeige und Zusammenfassung.

**Tech Stack:** Phaser 3.90, TypeScript, Vite, Vitest (keine neuen Abhängigkeiten)

**Spec:** `docs/superpowers/specs/2026-11-23-m4-besucher-design.md`

## Global Constraints

- Keine neuen Abhängigkeiten in `package.json`.
- Module unter `src/building/`, `src/camping/`, `src/vehicles/`, `src/visitors/`, `src/economy/`, `src/core/` und die Daten-Module in `src/ui/` importieren **kein** `phaser`.
- Feldkoordinaten (`Cell`) beziehen sich immer auf das Grundstück (0..63, 0..47). Die Straße liegt **außerhalb**: Fahrspur hin `y = grid.height` (48), Fahrspur zurück `y = grid.height + 1` (49), jeweils über die ganze Kartenbreite (`x` von `-BORDER_TILES` bis `grid.width + BORDER_TILES - 1`).
- „An die Straße angeschlossen“ heißt: ein Weg-Feld auf der **untersten Reihe** (`y = grid.height - 1`) oder über Wege (4er-Nachbarschaft) mit einem solchen verbunden. Personal-Tore mit Weg darunter zählen als Weg, Schleusen nie.
- Fahrzeuge fahren nur auf Wegen (plus Straße und das letzte Stück auf der Zeltfläche zum Stellplatz). Gäste laufen über alles außer Zaun, Personal-Tor und Gebäude (8er-Nachbarschaft, keine Diagonale an einer Ecke vorbei).
- Zeit: Die Uhr zählt **Spielsekunden seit Tag 1, 00:00**. Ein Tick = **2 Spielsekunden**. **1 Spielstunde = 20 000 ms** bei Tempo 1. Tempo 1/2/3 = Faktor **1 / 2 / 4**. Höchstens **60 Ticks pro Bild**, der Rest verfällt.
- Festival: Start **Tag 1 10:00** (36 000), Anreise bis **Tag 1 18:00** (64 800), Abreise ab **Tag 4 10:00** (295 200), Abschleppen **Tag 4 14:00** (309 600). Höchstens **300 Gäste**, **2 Gäste pro Auto**, Stellplatz **2 × 2**.
- Bühne spielt **14:00–01:00**, Schlafenszeit **01:00–08:00**.
- Früher Heimfahren: Zufriedenheit **unter 25 %** für **2 Spielstunden** (7 200 s).
- Gäste zahlen nichts, die Kasse ändert sich durch M4 nicht. Zeltflächen kosten nichts.
- Simulation nur über `Random` mit festem Startwert, nie `Math.random()`; gleiche Startwerte → gleicher Ablauf, unabhängig vom Tempo.
- Alle sichtbaren Texte auf Deutsch. Platzhalter-Grafiken nur per Code in `src/assets/placeholders.ts`. Alles muss bei **320 × 180** Spielpixeln passen und lesbar sein.
- Alle Tests aus M1–M3 laufen weiter; angepasst werden sie nur dort, wo sich eine Signatur oder die Lieferregel ändert.
- Commit-Nachrichten auf Deutsch mit Präfix `M4:` und den Attributionszeilen der Sitzung.

## Review Focus

1. **Weg unter einem fahrenden Auto wird abgerissen** → Auto bleibt mit Warnsymbol stehen, fährt nach dem Wiederaufbau weiter; nie über die Wiese. → Task 9 (`abgerissener Weg stoppt das Auto, Wiederaufbau löst es`).
2. **Stand verliert mitten im Festival seinen Lieferweg, während Gäste anstehen** → Schlange löst sich auf, die Gäste suchen ein anderes Angebot. → Task 7 (`geschlossener Stand löst die Schlange auf`), Task 10 (`Gast aus aufgelöster Schlange sucht neu`).
3. **Zaun wird über stehende Gäste gezogen** → Gäste stehen sofort auf dem nächsten begehbaren Feld, nie im Zaun. → Task 10 (`Gast auf blockiertem Feld weicht aus`).
4. **Browser-Tab war minutenlang im Hintergrund** (riesiges `delta`) → höchstens 60 Ticks werden nachgeholt, kein Einfrieren. → Task 1 (`consume begrenzt auf 60 Ticks`).
5. **Tempo 3 statt Tempo 1** → gleicher Zustand zur gleichen Spielzeit. → Task 9 (`Tempo ändert den Ablauf nicht`).

**Interfaces:**

  - `export const TIME = { tickSeconds: 2, realMsPerGameHour: 20000, speedFactor: { 1: 1, 2: 2, 3: 4 }, maxTicksPerFrame: 60 } as const;`

- Produces (`src/core/clock.ts`):
  - `export type Speed = 1 | 2 | 3;`
  - `export class GameClock { constructor(second: number); second: number; paused: boolean; speed: Speed; setSpeed(s: Speed): void; togglePause(): void; step(): void /* second += TIME.tickSeconds */; consume(realMs: number): number }` – `consume` sammelt echte Millisekunden (Rest bleibt erhalten), liefert die Anzahl fälliger Ticks; pausiert → 0 und nichts wird gesammelt; mehr als `maxTicksPerFrame` → genau `maxTicksPerFrame`, der Überschuss wird verworfen. Ein Tick dauert bei Tempo 1 genau 100/9 ms; gerechnet wird ganzzahlig (`Zähler += realMs × Faktor × 9`, je 100 ein Tick), damit verschiedene Tempi ohne Rundungsfehler auf dieselbe Tickzahl kommen.
  - `export function dayOf(second: number): number` (Tag 1 = 0 … 86 399), `export function minuteOfDay(second: number): number`
  - `export function isStageTime(second: number): boolean`, `export function isSleepTime(second: number): boolean`
- Produces (`src/core/random.ts`): `export class Random { constructor(seed: number); next(): number /* [0,1) */; int(min: number, maxExclusive: number): number; pick<T>(items: readonly T[]): T }` (mulberry32)
- Produces (`src/ui/festivalText.ts`):
  - `export function clockLabel(second: number, speed: Speed, paused: boolean): string` → `Tag 1 · 10:00 · Tempo 1` bzw. `Tag 2 · 07:05 · Pause`
  - `export function statsLabel(guests: number, satisfaction: number): string` → `Gäste: 84 · Zufriedenheit: 72 %`
  - `export const START_LABEL = 'Festival starten';` `export const START_MISSING = 'Zeltfläche mit Weg zur Straße fehlt';`

**Interfaces:**
- Produces (`grid.ts`):
  - `CellChange` bekommt `camp?: boolean`.
  - `Grid.isCamp(x, y): boolean` (außerhalb → false)
  - `Grid.isOccupied(x, y): boolean` – Feld gehört zu einem zugeteilten Stellplatz (Zelt/Auto)
  - `Grid.setOccupied(cells: readonly Cell[], on: boolean): Cell[]` – liefert und meldet nur wirklich geänderte Felder
  - `Grid.clear(cells)` entfernt zusätzlich die Zeltflächen-Markierung; `isOccupied` bleibt unverändert.
- Produces (`rules.ts`): `BuildKind` = `'path' | 'fence' | 'visitorGate' | 'staffGate' | 'camp'`. `verdict` für alle Arten: belegtes Feld (`isOccupied`) → `'blocked'`. `'camp'`: Gebäude oder `structureAt !== 'none'` → `'blocked'`, schon markiert → `'skip'`, sonst `'build'` (Weg erlaubt). `'fence'`, `'visitorGate'`, `'staffGate'` auf markiertem Feld → `'blocked'`. `changeFor(grid, 'camp', x, y)` → `{ x, y, camp: true }`.
- Produces (`placement.ts`): `placementVerdict` gibt `'blocked'` auch bei `isOccupied`.
- Produces (`autotile.ts`):
  - `pathMask`: ein Weg auf der untersten Reihe hat zusätzlich `DIR.S` (Anschluss an die Straße).
  - `export function campMask(grid: Grid, x: number, y: number): number` – Nachbarn mit Zeltflächen-Markierung (0 … 15).

    2. `leaving` und nicht schon `toTent/inTent` mit `'leave'` → aus einer Schlange austreten, `toTent` mit `findPath` zur Tür, `purpose 'leave'`.

    8. `watch`: stehen bleiben; Bühne zu, Musik ≤ 0 oder ein anderes Bedürfnis `>= urgentAt` → `wander`.
